INSTALL:
1. In Supabase SQL Editor, run SUPABASE-v015-PHOTO-DELETE.sql once after v014. Success/no rows returned is expected. This adds permissions only and deletes no photos.
2. Replace memories.js in the repository root and let the site deploy.
3. Refresh the app. Under the test photo, tap Delete photo and confirm.

The shared copy is removed for everyone; originals on phones are untouched. Family profiles can delete any trip photo. Names remain unverified labels under the previously chosen shared-link model; Guest read-only remains a UI behavior. Backend access uses the same shared-link permissions as uploads.

Storage is removed first; its successful removal is checked before deleting metadata. If cleanup of a gallery entry fails after storage removal, a retry can finish it. If storage blocks deletion, the gallery entry remains and an error is shown. No planning, voting, packing, card or itinerary data is changed. Migrated v013 photo paths and newer shared paths are supported.
